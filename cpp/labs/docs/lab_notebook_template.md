# Lab notebook template

Copy this into a `LAB_NOTES.md` of your own (for example `cpp/labs/LAB_NOTES.md`) and fill in one block per lab. Writing the prediction down *before* running is the point: it shows you what you actually believed.

```markdown
## Lab NN: <name>, <date>

### Conditions
- Plugged in? Governor? Pinned to a core? Other programs running?
- Compiler and flags (if you changed them):

### Predictions (before running)
1.
2.
3.

### Results
| Run / variation | Number(s) I got | Matched my prediction? |
|:---|:---|:---|
|  |  |  |

### Break-it variations
- Change:            Predicted:            Got:
- Change:            Predicted:            Got:

### Explanations (in my own words, no notes)
1.
2.

### What surprised me / what I'd check next
-
```

Tips:
- **Record conditions every time.** Laptop numbers depend on power, temperature and background load, and you'll want to know why two runs differ.
- **Write numbers with units** (ns, µs, ms, GB/s).
- **When a prediction was wrong, write down why** once you understand it. That line is the actual lesson.
